# 입찰일지 자동화 시스템 - 나라장터 프록시 서버

`입찰일지_자동화_시스템.html` 화면이 나라장터(G2B) 입찰공고를 검색조건별로 조회할 수 있게
해주는 중계 서버입니다. 어제 만든 `nara-bid-proxy`(안전보건관리계획서 시스템용)와 완전히
같은 원칙으로 만들어졌습니다 — 서비스키는 이 서버의 `.env`에만 있고, 화면(브라우저)에는
절대 노출되지 않습니다.

## 실행 방법

```bash
cd bidlog-server
npm install
cp .env.example .env
```

`.env`를 열어 `NARA_SERVICE_KEY`에 data.go.kr에서 발급받은 서비스키를 붙여넣으세요.
(어제 안전보건관리계획서 프로젝트에서 쓰던 것과 같은 키를 재사용해도 됩니다.)

```bash
npm start
```

정상 기동 시:
```
[bidlog-proxy] 서버 실행 중 → http://localhost:8788
```

## 확인

```bash
curl http://localhost:8788/health
curl "http://localhost:8788/api/bidlog?startDate=2026-07-01&endDate=2026-07-31"
```

## ⚠️ 알려진 한계 (내일 테스트하면서 같이 고칠 부분)

이 API의 응답 필드 중 **기초금액, 개찰일시, 투찰마감일시, 업종제한**의 정확한 필드명은
data.go.kr 공식문서 페이지가 자동 접근을 차단하고 있어 100% 검증하지 못했습니다.
`server.js`의 필드 매핑 부분에 여러 후보 필드명을 나열해두었고, 각 결과 항목에는
`raw`(원본 응답 전체)를 함께 내려주도록 해뒀습니다.

화면 결과 표에서 특정 칸이 계속 "—"로 비어 보이면:
1. 그 행의 "원본" 링크를 눌러 실제 응답 JSON을 확인
2. 거기 있는 진짜 키 이름을 캡쳐해서 알려주면
3. `server.js`의 해당 매핑 한 줄만 바로 고치면 됩니다.

(어제 안전보건관리계획서 프로젝트에서 API 엔드포인트 오타, 검색어 필터링 문제를
잡았던 것과 같은 방식의 디버깅입니다.)

## "투찰마감일시 기준 검색"의 근사치 처리

이 API는 게시일시(1) 또는 개찰일시(2) 기준 조회만 공식 지원하는 것으로 보입니다.
투찰마감일 기준으로 검색할 때는, 요청 기간보다 45일 앞선 게시분까지 넉넉히 가져온 뒤
실제 마감일시(`bidClseDt`)가 요청 기간에 들어오는 것만 다시 걸러내는 방식으로
근사 처리했습니다. 결과가 이상하면 이 로직(`server.js`의 `dateType === "close"` 부분)을
같이 조정하면 됩니다.

## 배포 (NHN Cloud 등)

어제와 완전히 같은 순서입니다:
1. WAS 서버에 `git clone` (또는 `cat > server.js << 'EOF'`)로 파일 배치
2. `npm install`, `.env` 설정
3. `pm2 start server.js --name bidlog-proxy` (안전보건관리계획서용 `nara-proxy`와 이름만 다르게)
4. WEB 서버 nginx에 이 서비스용 `location` 블록 추가, 또는 별도 서브도메인/포트로 분리
5. 화면의 "프록시 서버 주소"에 실제 서버 주소 입력
